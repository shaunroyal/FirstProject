# Documentation style

- Write for a new team member. Use short sentences, active voice and plain words.
- Put the most important information first. Use headings, lists and tables to help readers scan.
- Show commands exactly as they are run, in fenced code blocks with a language tag.
- Link to the source of truth instead of copying it. Commands live in `AGENTS.md`.
- Use relative links for files in the repo.
- Never include secrets, internal-only URLs or customer data.
- Record significant decisions as ADRs in `docs/decisions/`, not in README files.
